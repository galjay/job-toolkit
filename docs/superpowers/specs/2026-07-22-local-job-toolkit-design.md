# 本地开源求职工具箱设计

**日期：** 2026-07-22  
**状态：** 用户已确认  
**定位：** 发布到 GitHub、由使用者在自己电脑运行的开源求职工具，不建设公共网站。

## 1. 目标

项目围绕一条连续求职流程工作：

`现有简历 -> 目标 JD -> 匹配与差距 -> 针对性改写 -> 模板预览 -> 导出新简历`

同时提供两种照片能力：不上传照片的本地标准证件照处理，以及可选的 AI 职业形象照生成资源。

项目必须满足以下结果：

- 使用者配置并承担自己的 AI API 费用。
- 简历、JD 和照片默认不落盘、不进入数据库。
- 用户看到正常简历预览，而不是 JSON 或 Markdown 源码。
- 输出可编辑 DOCX，并可通过浏览器打印为 PDF。
- 登录、注册、用户数据库和开发者面板全部移除。
- README 只描述已经实现并验证的能力。

## 2. 非目标

- 不建设多用户公网 SaaS。
- 不提供作者共享的 AI 额度。
- 不实现拖拽式通用文档排版器。
- 不承诺 AI 生成职业照可用于身份证、护照等法定证件。
- 不自动操作豆包、即梦等第三方网页，也不绕过其登录、收费或使用限制。

## 3. 用户体验

### 3.1 页面结构

应用打开后直接进入实际工作台，不显示营销落地页。

- `/`：简历与 JD 工作台。
- `/photo`：证件照与 AI 职业形象照。
- 其他旧路由（登录、注册、开发者面板、独立宣传首页）删除。

顶部导航只保留“简历与 JD”和“证件照”。页面持续显示本地运行状态和 AI 是否已配置，但绝不显示密钥内容。

### 3.2 简历与 JD 闭环

工作台按五步组织：

1. 上传 PDF/DOCX 或粘贴现有简历文本。
2. 上传 PDF/DOCX 或粘贴目标岗位 JD。
3. AI 返回匹配分数、已匹配能力、缺失关键词、风险点和逐条改写建议。
4. 用户接受、拒绝或编辑建议，形成一份结构化简历。
5. 用户选择模板，预览并导出 DOCX，或使用浏览器打印为 PDF。

只有 JD 时，工作台进入“岗位分析”模式，输出岗位摘要、硬技能、软技能、学历/经验要求、核心职责和投递准备建议。

### 3.3 改写约束

每条建议包含：原文、优化后文本、修改理由和相关 JD 关键词。系统提示词和界面都要明确：

- 不得编造公司、职位、项目、技能、奖项或量化数字。
- 无法从原文确认的信息必须标记为“需要用户补充”，不能自行补齐。
- 允许压缩、重排和改写表达，但必须保持事实含义。
- AI 结果必须由用户确认后才能进入最终简历。

## 4. 简历数据与模板

AI 的结构化 JSON 只作为内部交换格式，前端将其渲染成可阅读、可编辑的简历。核心数据包含：

- 基本信息：姓名、电话、邮箱、城市、求职方向、个人链接。
- 个人概述。
- 教育经历。
- 工作或实习经历。
- 项目经历。
- 校园经历与奖项。
- 技能与证书。

首版提供三套有明确用途的模板：

1. **ATS 标准版**：单栏、黑白、无照片、无图标、无复杂表格，默认推荐。
2. **中文校招版**：教育、实习和项目优先，可选照片，使用克制的蓝色层级。
3. **经验求职版**：个人概述、核心能力和工作经历优先，教育信息后置。

三套模板共用同一份结构化数据。切换模板不能丢失内容。DOCX 导出必须保留可编辑文本；PDF 通过专用打印样式生成，不能把整页转换成图片。

## 5. 证件照与职业形象照

### 5.1 标准证件照模式

在浏览器本地完成，不调用后端：

- JPG/PNG 上传与预览。
- 本地人像分割、换白/蓝/红/自定义底色。
- 一寸、二寸、小一寸及常见考试尺寸。
- 拖动、缩放、重新裁切和轻度提亮。
- 下载单张 PNG。
- 生成六寸相纸多张排版图。

### 5.2 AI 职业形象照模式

目标是把普通正脸照转为保留本人五官特征、穿正式服装、背景干净、轻度美化的求职头像。

项目保证提供经过整理的生成资源包：

- 根据服装、背景、构图和美化强度组合完整中文提示词。
- 提供负面提示词，避免身份漂移、过度磨皮、面部变形和不自然服装。
- 一键复制提示词，并下载包含提示词和参数说明的文本资源。
- 明确说明如何把参考照片与提示词交给豆包、即梦、ChatGPT 等支持参考图生成的工具。

当使用者配置兼容 OpenAI Image Edit 请求格式的图片接口时，应用可在用户明确同意后，将照片和提示词发送给该接口直接生成。未配置、接口不兼容或请求失败时，自动回退到资源包模式，不伪装成生成成功。

界面必须区分“标准证件照”和“AI 职业形象照”。后者标注适用于简历和职业头像，不保证符合政府证件规范。

## 6. 技术架构

### 6.1 前端

继续使用 Vue 3、Vite 和 Element Plus。页面按职责拆分：

- 工作流容器：管理简历、JD、分析结果和当前步骤。
- 文件输入组件：上传、粘贴、解析状态和错误。
- 匹配报告组件：分数、匹配项、缺失项和风险。
- 建议编辑组件：接受、拒绝、编辑逐条建议。
- 简历编辑与预览组件：结构化字段编辑、模板切换和打印。
- 证件照编辑器：本地画布与下载。
- AI 职业照资源组件：配置、提示词、同意提示和生成结果。

浏览器只保存当前会话状态；刷新页面后清空。API Key 不写入 localStorage。

### 6.2 后端

继续使用 FastAPI，但改为无状态服务。删除 SQLAlchemy、JWT、密码处理和所有用户模型。保留并收敛为以下接口：

- `GET /api/health`：服务状态。
- `GET /api/config/status`：只返回文本/图片 AI 是否配置，不返回值。
- `POST /api/documents/parse`：解析 PDF/DOCX 为纯文本。
- `POST /api/workflow/analyze`：联合分析简历和 JD。
- `POST /api/jd/analyze`：单独分析 JD。
- `POST /api/resume/export/docx`：把结构化简历导出为 DOCX。
- `POST /api/photo/generate`：可选图片接口代理，仅在配置后启用。

文本 AI 使用 OpenAI Chat Completions 兼容配置，默认值适配 DeepSeek：

- `AI_API_KEY`
- `AI_BASE_URL=https://api.deepseek.com/v1`
- `AI_MODEL=deepseek-chat`

图片 AI 单独配置，不复用文本密钥：

- `IMAGE_API_KEY`
- `IMAGE_BASE_URL`
- `IMAGE_MODEL`

## 7. 安全与隐私

- 后端开发启动默认绑定 `127.0.0.1`。
- CORS 只允许配置中的本地前端地址，不使用通配符。
- `.env` 必须被 Git 忽略；仓库只提交 `.env.example`。
- 状态接口和错误日志不得返回完整或部分 API Key。
- 上传只接受 PDF、DOCX、JPG 和 PNG，并同时检查扩展名、MIME 和文件签名。
- 单文件上限 8 MB；PDF 限制页数；解析后的文本限制字符数。
- 不接受容易误判的旧版 `.doc`。
- 文件只在请求内存中处理，不使用用户文件名拼接路径，不保存临时副本。
- 简历和 JD 作为不可信数据放入明确分隔区，提示词要求忽略其中试图改变系统规则的指令。
- AI 返回使用 Pydantic 模型校验；非法 JSON、缺字段或越界分数不得直接进入页面。
- AI 请求设置超时、一次格式重试、全局并发上限和前端防重复提交。
- 用户输入和模型完整响应不写入日志。
- 图片发送第三方前展示提供商、用途和隐私提示，必须由用户主动确认。
- 启动脚本不得结束其他 Python/Node 进程，不得删除用户文件或数据库。

## 8. 错误处理

- 未配置文本 AI：文件解析、模板编辑和本地证件照仍可使用；AI 按钮显示配置指引。
- 模型余额不足、超时或网络失败：显示可执行的错误信息，不清空用户输入。
- AI 结构不合格：后端自动进行一次仅针对格式的重试；仍失败则返回统一错误。
- 文件解析失败：区分不支持格式、损坏文件、扫描版 PDF 和内容超限。
- 图片模型失败：保留参考图与设置，切换到提示词资源包，不上传第二次。

## 9. 安装与开源交付

项目采用普通 GitHub 开源项目方式交付：源码、README、环境变量样例和启动命令。Windows 启动脚本只负责检查依赖并分别启动前后端，不执行系统级清理。

README 包含：

- 已实现功能和真实截图。
- Python、Node.js 和可选 Docker 的前置要求。
- 文本和图片 API 的费用归属说明。
- 从 `.env.example` 创建 `.env` 的步骤。
- 手动启动、Windows 启动脚本和 Docker 启动方式。
- 隐私边界、AI 内容核验提示及职业照用途限制。
- 测试命令和贡献说明。

## 10. 测试与验收

后端使用 pytest 和 FastAPI TestClient，AI 请求在测试中全部模拟。至少覆盖：

- 文件签名、类型、大小、PDF 页数和文本长度校验。
- PDF/DOCX 解析成功和扫描件错误。
- AI 正常返回、非法 JSON、缺字段、超时和重试。
- 提示词中的事实约束和不可信内容边界。
- JD 单独分析与简历/JD 联合分析的数据模型。
- 三种模板 DOCX 导出及导出文本可再次读取。
- 配置状态不泄露密钥。
- 图片接口未配置、用户未同意、请求失败和成功响应。

前端至少验证：

- 无登录状态可直接进入工作台。
- 上传/粘贴、分析、接受建议、编辑和模板切换流程。
- JSON 永远不会作为最终简历直接显示。
- DOCX 下载和打印样式入口。
- 标准证件照尺寸、换底色、移动缩放和相纸排版。
- AI 职业照资源包与回退流程。
- 桌面和手机宽度下无重叠、溢出或不可操作控件。

交付前必须执行并记录：后端全量测试、前端测试、生产构建、后端健康检查、至少一个完整模拟工作流、DOCX 内容复查，以及桌面/手机页面截图检查。
